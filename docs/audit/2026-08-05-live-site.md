# Live-site audit — 2026-08-05

A health-and-correctness audit of the live deploy at commit `797d332`, run
against production with `curl` rather than read from source.

This is an audit, not a state file: it is dated and it is not updated in place.
Current expected state per route lives in `docs/pages/` and `docs/endpoints/`.

- Live: 40 content-page URLs (20 pages × 2 languages), 29 non-page routes swept
- Predecessor: `docs/audit/2026-08-01-post-decomposition.md`

**Result: the site is healthy.** Every route answers, every cross-cutting
invariant holds, and the data is sane. One real defect was found, and it is a
monitoring blind spot rather than a broken page — finding A1.

Every claim below was checked against the live site. Where a check came back
clean it is recorded in section (b), because "we looked and it was fine" is the
part that rots silently.

## a. Findings

### A1. An aging pollen count is invisible to `/api/health`

The live pollen count is for **Friday 2026-07-31** — 5 calendar days, 3 business
days, before the audit date. `/api/health` reports that feed as `ok` /
`freshness: fresh`, and the overall report as `ok`.

**The staleness is upstream, not ours.** The Houston Health Department's index
lists only two dated slugs, `july-30` and `july-31`:

```
$ curl -s https://www.houstonhealth.org/services/pollen-mold   # 200, 129,574 bytes
  → dated count slugs on the index: 2
    2026-07-31  /services/pollen-mold/houston-pollen-mold-count-friday-july-31-2026
    2026-07-30  /services/pollen-mold/houston-pollen-mold-count-thursday-july-30-2026
```

and the predictable slugs for the three business days since all 404:

```
404  monday-august-3-2026
404  tuesday-august-4-2026
404  wednesday-august-5-2026
404  saturday-august-1-2026
```

So HHD has genuinely not published since Friday Jul 31. `fetchPollen()` is
correctly picking the newest count that exists, and `/pollen` labels it
honestly — "Count for Friday, Jul 31 · new counts publish weekday mornings."
Nothing in the fetch or render path is wrong.

**The defect is that nothing can see it.** `/api/health` judges pollen freshness
from `data.updated` — the KV *write* time — which the cron rewrites every ~2h
whether or not `countDate` moved. If HHD never publishes again, health stays
green indefinitely while `/pollen` serves an ever-older count. That is precisely
the early warning `/api/health` exists to give, and it is missing.

The current rationale, in `src/api/health.js` at the pollen feed, is:

```js
// countDate is the day the count is FOR; weekends legitimately carry
// Friday's, so it is reported but never used to judge freshness.
```

That is right for a 1–3 day gap and does not cover an open-ended one.

**Precedent for the fix is already in the same file.** The `weather` feed's
`shape()` tests whether the forecast *window* has elapsed, with the comment:

```js
// Has the forecast WINDOW itself elapsed? `updated` only says when we
// last fetched; NWS can hand back a product whose periods have all run
// out, and that parses perfectly.
```

Pollen's `countDate` is the same failure mode — a fresh write of stale content —
and has no equivalent check. Filed as issue **#156** with a full implementation
sketch; not fixed here, at the owner's direction.

Note the correct severity is `degraded`, not `unhealthy`: a 5-day-old count is
real, usable, honestly-labelled data, not malformed. Pollen is non-critical, so
that is a `200` with detail in the body and no `503`.

### A2. Issue #93 was delivered but left open

#93 ("Pollen: add pollen counts to the site") was still open with label
`backlog` despite being fully shipped — HHD is the source it named, `/pollen`
has its own page, `get_pollen` is live, `/api/pollen` is public, and the count
is labelled measured per the AQI precedent. Closed as part of this audit.

The other three open backlog issues (#94 lightning, #95 tides, #96 historical
weather) are genuinely unstarted and were left alone.

Detail on the ones where a clean result is easy to get wrong:

**Both languages, every page.** All 40 URLs, not a spot-check — the rule that
exists because `/es/hourly` once sat 502 for two deploys behind a green
English-only sweep. Spanish pages run 3–7 % larger than their English
counterparts, consistent with longer copy and no missing blocks.

**`http://www` in one hop.** `http://www.crosbynews.com/` → `301` →
`https://crosbynews.com/` directly, not via `https://www`. The `(not ssl)`
clause in the Redirect rule is doing its job. This is the check that
intermittently false-fails from a sandbox; it was clean here.

**The Spanish-link invariant.** One anchor on `/es/developers` points at `/mcp`.
That is the documented `ES_LINK_ALLOW` exception in `scripts/check-renders.mjs`,
and it is legitimate *only* while a separate, clearly-labelled `/es/mcp` link
sits beside it. Both were verified present on the live page:

```
/mcp — endpoint MCP (POST JSON-RPC) — el servidor funciona solo en inglés
/es/mcp — pági[na explicativa]
```

**The `SKILL.md` digest.** `/.well-known/agent-skills/index.json` publishes
`sha256:59bd8adc5a87b88d925e4854f7aad5134f362ac715ab741cc0365e3a94a63228`; the
SHA-256 of the live `SKILL.md` body (2,692 bytes) is byte-identical. This is the
check that would otherwise break silently.

**The CSP hash.** The homepage serves exactly one non-JSON-LD inline script
(2,312 bytes), whose SHA-256 is `vJRxS1csWSopr9R8FyjoJ1lpo3prHr6sRiX6LTB2N60=`
— the first of the three hashes advertised in the `script-src` directive. The
`'unsafe-inline'` alongside it is the documented backward-compat fallback, which
hash-aware browsers ignore.

**Air quality is measured, not modeled.** `usAqi: 77`, dominant PM2.5, from
named TCEQ monitors — PM2.5 "Baytown C148", ozone "Baytown Garth C1017", PM10
"Clinton C403" — with the Channelview C15 cross-reference monitor reporting
ozone 22 at 8.5 mi. The AirNow path is working; the Open-Meteo fallback is not
being exercised.

## c. Non-findings worth recording

**A transient `nearbyOzoneMonitor: "not reporting"`.** Seen mid-audit at the
22:30 cron tick, resolved to `"reporting"` at the 22:45 tick with the same
observation hour (21:00Z). That is AirNow's hourly post landing between ticks,
not a fault — the card hides gracefully in the gap, as designed.

**`/sitemap` does not list `/robots.txt`.** It lists `/sitemap.xml`, `/llms.txt`,
`/manifest.json`, the favicons and `/.well-known/api-catalog`, so the omission
looks inconsistent at a glance. It is not a drift: `docs/pages/sitemap.md`
documents the four groups and `robots.txt` is in none of them. Crawlers find
`robots.txt` by convention and never need a link. Left as-is deliberately.

**`"sin datos"` on `/es/about`.** Flagged by a text scan for outage language;
it is the privacy sentence ("sin cookies, sin anuncios, sin rastreadores, sin
datos personales"), not a data-outage state. False positive.

**`/api/tropics` is 126 bytes.** An empty `storms: []` is the normal
quiet-basin state, which the health shape check already encodes.

## d. How to re-run this

The route sweeps, header checks, canonicalization, negotiation and 404 checks
are all encoded in `/verify-site` — run that rather than re-deriving them. The
checks specific to this audit:

```bash
# PAGE_PATHS vs sitemap.xml — exact set match, both directions
curl -s https://crosbynews.com/sitemap.xml | grep -o '<loc>[^<]*</loc>' \
  | sed 's/<[^>]*>//g;s|https://crosbynews.com||' | sort

# SKILL.md digest vs the published one
curl -s https://crosbynews.com/.well-known/agent-skills/crosby-weather/SKILL.md \
  | sha256sum
curl -s https://crosbynews.com/.well-known/agent-skills/index.json

# MCP version agreement: server.json, MCP_SERVER_INFO, and the registry
curl -s "https://registry.modelcontextprotocol.io/v0.1/servers?search=com.crosbynews/weather"

# All 13 tool names present on each hand-maintained surface
curl -s https://crosbynews.com/llms.txt
curl -s https://crosbynews.com/.well-known/agent-skills/crosby-weather/SKILL.md
curl -s https://crosbynews.com/developers
curl -s https://crosbynews.com/es/developers
# plus README.md in-repo

# Pollen count age — the A1 check, until #156 lands
curl -s https://crosbynews.com/api/pollen   # compare countDate against today (CT)
```

The Spanish-link invariant and the cross-module reference rules are enforced by
`scripts/check-renders.mjs` and `scripts/check-module-refs.mjs` in the required
CI job, so they need no manual sweep — the live check above was confirmation,
not the gate.
