# Live-site audit — 2026-08-26

Exhaustive audit of the live deploy at commit `99edc21`, run against
`https://crosbynews.com` rather than against the code or CLAUDE.md. Every claim
below came from a request to the live site, the deployed bundle, or the source —
none from prose.

This is an audit, not a state file: it is dated and is not updated in place.
Current expected state per route lives in `docs/pages/` and `docs/endpoints/`.

- Live: 42 content-page URLs (21 pages × 2 languages), 33 non-page routes
- Predecessor: `docs/audit/2026-08-05-live-site.md`

**Nothing user-facing was broken.** All eight findings are in CI and docs, and
all eight are fixed in the PR that carries this file — the first batch under the
owner policy set the same day (audit findings go in one PR, two at most).

## (a) Findings

### a.1 — The Syntax check gate never ran the homepage renderer

The one with teeth. `scripts/check-renders.mjs` exists because `/es/hourly`
shipped a 502 that `node --check`, the dry-run and the static check all passed:
a Spanish-only branch referenced an unimported name. The gate's method is to
*call every renderer in both languages* and fail on `ReferenceError`.

It called `homeHtml` and `homeMarkdown` as `fn(DATA, lang)`. Both take seven
parameters — `(weather, water, news, cal, tropics, burnban, lang)` — so `lang`
landed in the `water` slot, `news` was `undefined`, and `news.items` threw a
`TypeError`. Only `ReferenceError` is recorded as a failure, so the throw was
swallowed and the gate reported OK.

Two consequences, both silent:

- The homepage renderer's body **never executed** under either language. A
  `ReferenceError` anywhere in it would have shipped with three green gates —
  on the site's most-trafficked page, the one that fans out to six datasets.
- `/es` dropped out of the Spanish-links check. The script's own summary line
  said "20 Spanish pages" on a 21-page site; nothing compared that against 21.

The script had predicted exactly this in a comment about `ONE_ARG_LANG`:
"calling one wrongly makes it bail early and silently stop covering its own
body." The mechanism was known; nothing enforced it.

**Fixed** two ways. `homeHtml`/`homeMarkdown` get their own call shape, and any
`*Html` export that does not return a string is now a hard failure rather than a
silent skip — a wrong call shape can no longer pass. Verified by mutation:
breaking the new call shape makes the gate exit 1 naming both languages. The
summary now reads 21.

### a.2 — `docs/endpoints/README.md` asserted the opposite of the truth about `/mcp`

> **No route in this directory is in `PAGE_PATHS`** — including `/mcp`.

Live, both `GET /mcp` and `POST /mcp` carry
`link: <https://crosbynews.com/mcp>; rel="canonical"`, as does `/es/mcp`;
`/api/weather` (a genuine non-`PAGE_PATHS` route) does not. CLAUDE.md documents
the real behaviour, including that `PAGE_PATHS` matches on pathname not method.

Provenance: the 2026-08-01 audit filed `/mcp` being outside `PAGE_PATHS` as
finding d.4. It was fixed in the code; this file was never updated, so it kept
asserting the pre-fix state. **Fixed.**

### a.3 — "nine public data APIs" in six places; there are ten

`/api/burn-ban` was added and nothing recounted. The api-catalog lists ten
anchors: air, burn-ban, calendar, fishing, news, pollen, traffic, tropics,
water, weather.

Stale in `docs/endpoints/README.md` (×2), `docs/endpoints/api/README.md`,
`docs/endpoints/openapi.json.md`, `docs/endpoints/llms.txt.md` and
`docs/pages/sitemap.md`. The `llms.txt.md` copy was worse than a count: its
enumeration named nine APIs and omitted burn-ban, while the live `/llms.txt`
correctly names all ten. `docs/pages/sitemap.md` contradicted itself in
consecutive lines ("all ten `/api/*` endpoints", then "the nine public data
endpoints plus `/api/health`").

The 2026-08-01 audit had already settled "ten" for the README (finding c.1); the
word "nine" survived everywhere else. **Fixed**, enumeration included.

### a.4 — `/api/burn-ban`'s doc was filed outside `api/`

It sat at `docs/endpoints/burn-ban.md` while the other ten `/api/*` docs live in
`docs/endpoints/api/`, against that README's own "Files mirror route paths."
Same root cause as a.3. **Fixed** — moved to `docs/endpoints/api/burn-ban.md`.

### a.5 — CLAUDE.md page counts stale in three places

"the 20 English content paths + their `/es` counterparts, 40 total" — it is
21 and 42. `/verify-site` described as checking "all 20 content pages" while its
own SKILL.md says 21. `src/index.js`'s header comment said "the 40 content
paths". `docs/pages/` correctly holds 21 files. **Fixed** in all three.

### a.6 — Cloudflare Speed Brain is on, and was undocumented

Every response carries `speculation-rules: "/cdn-cgi/speculation"`, an
edge-served prefetch ruleset (`cf-speed-brain`, `conservative`, `href_matches:
"/*"`) that makes visitors' browsers prefetch same-origin links. Zero mentions
of speculation, prefetch or Speed Brain existed anywhere in the repo.

This is the class of thing `docs/ops/cloudflare-zone.md` exists to track — its
section "Edge features can rewrite a response after the Worker returns it" was
written after Cloudflare Web Analytics injected a tracker for months. Speed
Brain is **not** that: nothing third-party loads, and the HTML body is
byte-identical between a real browser UA and a plain `curl` (26104 bytes each),
so the no-third-party-analytics claim on `/privacy` and `/about` still holds.
But it does mean the origin sees GETs for pages nobody opened, which any future
traffic counting must account for. **Fixed** — recorded in that file.

### a.7 — Content pages answered any HTTP method with 200

`PUT`, `DELETE` and `PATCH` on `/` returned 200 and the full page, while
`/icons/*` already answered 405 — same site, two answers. Nothing was at risk
(no content page mutates state, and Cloudflare does not cache a non-GET).

**Fixed** — content pages are GET/HEAD only, 405 with `Allow: GET, HEAD`. The
two `/mcp` paths are exempt and keep the router's own method handling: `POST
/mcp` is the protocol, and `/es/mcp` answers non-GET/HEAD with the 404 that
`/developers` documents in both languages. Unknown paths still 404, not 405.

### a.8 — A bad icon path surfaced as 502 rather than 404

The `/icons/*` proxy mapped only a literal upstream 404 to 404; every other
non-OK status became 502. NWS answers a malformed icon path with a different
4xx, so `/icons/land/day/skc.png` — a real icon written with an extension NWS
paths do not carry — read as a gateway error blaming our upstream. **Fixed**:
any upstream 4xx is a 404, 5xx stays 502.

## (b) Checked and clean

Recorded because "we looked and it was fine" is the part that rots silently.

**Routes.** All 42 content pages return 200 and are substantive in both
languages (11.6–42.9 KB). All 33 non-page routes return 200 with correct
content types.

**Integrity of what we publish.** The CSP's three script hashes map exactly to
`HOME_SCRIPT`, `PUSH_CLIENT_SCRIPT` and `NEWS_ADMIN_SCRIPT`; `/sw.js` is
byte-identical to `SW_SCRIPT`; the SHA-256 that
`/.well-known/agent-skills/index.json` publishes matches the SKILL.md it serves.
`sitemap.xml`'s 42 URLs equal `PAGE_PATHS` exactly, with correct
`en-US`/`es-MX`/`x-default` alternates on every entry.

**No edge injection.** Homepage body byte-identical under a real browser UA vs a
plain `curl`, zero `cloudflareinsights`/beacon/analytics references. Checked the
way `docs/ops/cloudflare-zone.md` requires, not by reading toggles.

**Headers.** HSTS, `x-frame-options`, CSP, COOP, `nosniff`, `referrer-policy`,
`permissions-policy` on every route sampled, including the new 405. The Worker's
`preload` token is still stripped by the zone's HSTS copy — documented and
deliberate, not a regression.

**HTML head, all 42 pages.** Correct single canonical, correct `html lang`,
unique `<title>` and meta description on every page, complete Open Graph set,
valid JSON-LD.

**Links.** All 64 distinct internal link targets return 200. Exactly one `/es`
page links to an English path — `/es/developers` → `/mcp`, the documented
`ES_LINK_ALLOW` exception — and its stated precondition holds live: the page
carries a separate, clearly-labelled `/es/mcp` link beside it.

**MCP.** 14 tools, all returning data. Protocol `2025-06-18`. Spec-correct
errors (`-32700` parse, `-32601` method, `-32602` unknown tool), 202 for
notifications, working batch, 405 for `Accept: text/event-stream`, 404 for
`POST /es/mcp`, correct CORS preflight. All six hand-maintained tool lists are
in sync — README, server-card, `llms.txt`, SKILL.md, `/developers`,
`/es/developers` — and `server.json` 1.7.0 matches `serverInfo`. This is the
trap CLAUDE.md flags as going stale silently; it had not.

**APIs.** All eleven responses conform to their OpenAPI schemas, with every
required field present. Every ETag revalidates to 304. CORS `*` on the public
surface, absent on `/api/news/delete`, which answers an unauthenticated POST
with 401.

**Not an open proxy.** `/icons/*` is prefix-locked and `..` cannot escape it;
`/radar-image` ignores injected query parameters. The push endpoint's SSRF
allowlist rejects a non-push host.

**Data.** Health green — cron 0.1 h old, every feed `ok: true`. The same
conditions agreed across the homepage, `/api/weather`, the MCP tool and
`/badge.svg`. Pollen's `countDate` matched the CT calendar day and its upstream
slug.

**Gates.** 39/39 `src/` files parse; contrast, module-reference and (after a.1)
render checks pass.

## (c) Method

The route sweep, header checks and canonicalization checks follow
`.claude/skills/verify-site/SKILL.md` and are not re-derived here. Beyond it,
this audit compared *published* artefacts against their *sources* rather than
re-reading either alone: CSP hashes against the script constants, the
agent-skills digest against the file it names, `sitemap.xml` against
`PAGE_PATHS`, live API bodies against the OpenAPI schemas, and the six MCP tool
lists against `tools/list`.

Two dead ends worth recording, both instances of the rule in CLAUDE.md that a
check reusing the code under test cannot falsify it:

- A regex for inline `<script>` flagged an unhashed 626-byte block on every
  page. It was the `application/ld+json` data block, which CSP `script-src` does
  not govern. Reading the block, rather than trusting the count, settled it.
- A first pass at a.1 used a hand-made fixture instead of the script's own
  `DATA` and wrongly implicated `trafficHtml`. Re-running the real script with
  instrumentation named `homeHtml`. The fixture has to be the one under test.
